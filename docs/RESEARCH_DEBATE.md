# Ten-agent research debate

## Decision

On August 12, 2026, ten independent Sol roles audited rules, comparable Google winners, current entrants, architecture, security, implementation, evaluation, demo, delivery, and product value.

The binding vote was unanimous in direction:

> **REVISE, then BUILD only if the 48-hour K0 falsification test passes.**

Taskmaster replaces Fortified Enterprise Fleet. The broad autonomous control plane is rejected in favor of one deep, real, human-gated transaction.

## Judge-style score range

The nine independent current estimates ranged from 32 to 69, with every evaluator noting a Stage One failure because no mandatory served Google implementation exists. The chair set the current counterfactual at **52/100** and the fully gated Taskmaster projection at **90/100**.

These are internal estimates under the official 40/30/30 rubric, not organizer scores or a guarantee.

## Comparable winner research

The studied set was twenty official winning projects from two comparable Google events—eight 2025 ADK winners and twelve 2026 Gemini Live winners—not twenty separate hackathons. Individual judge scorecards are unavailable, so findings are correlations:

- One instantly understandable job.
- Visible external action rather than chat.
- Google technology integral to the experience.
- A memorable operational, human, or physical consequence.
- One coherent live transformation.
- Honest proof and recoverable failure.

Agent count, service count, commit count, security complexity, and idea novelty alone were not reliable winning predictors.

## Resolved debates

### Track

Taskmaster wins. Fleet would require a cataloged institutional agent network, persistent memory, gateway/governance, and observability that do not belong in this focused product.

### IAM authority

Humans apply the reviewed provider/binding. `setIamPolicy` cannot restrict a compromised runtime to one exact member, so application validation is not claimed as an IAM boundary.

### Google runtime

One ADK service on Cloud Run wins over Agent Engine and a Python/Node split. Firestore exists for one-time challenge consumption and evidence-derived state. Cloud Tasks and Pub/Sub are removed. KMS follows K0.

### Model boundary

Gemini interprets redacted workflow evidence and diagnoses bounded failures. It never creates CEL, selects resource IDs, grants roles, writes shell commands, authorizes actions, or completes receipts. A deterministic compiler owns those decisions.

### Exact-key proof

The debate originally found only a partial ProofV2 payload primitive. The implementation now includes server-issued challenges, transactional consumption, completed-run/workflow/review GitHub observation, and ADC-backed Google `keys.get`. A fresh hosted run consumed one live Firestore challenge, matched the exact active key, and rejected replay; it remains readiness evidence because an independent protected-environment review was absent.

### Demo truth

The full cutover is asynchronous and cannot be honestly completed in four minutes. The video shows a timestamped reconstructable completed case and one unedited live authorized/hostile pair.

## Fatal objection and rebuttal

Objection: Google/GitHub already document WIF, StepSecurity finds replaceable secrets, and an LLM wrapper cannot prove all key consumers.

Rebuttal: Keyless does not sell detection or YAML. It proves the exact key, compiles a no-added-privilege trust path, opens a reviewed PR, tests authorized and hostile identities, waits for a human disable, verifies fresh legacy failure and post-disable continuity, and produces scoped evidence. Unknown external consumers produce `HOLD`; universal absence is never claimed.
